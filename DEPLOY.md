# Что важно знать при развёртывании

Не инструкция по nginx и systemd — только то, что вытекает из решений в коде
и о чём иначе узнаёшь уже на боевом сервере.

## 1. Node не ниже 22.5

БД работает на встроенном модуле `node:sqlite` — отдельный пакет не нужен и
`node-gyp` ничего не собирает. Но на Node 20 и старше модуля просто нет, и
сервер не стартует. Проверить: `node --version`.

## 2. JWT_SECRET обязателен в production

При `NODE_ENV=production` сервер **откажется стартовать** без переменной
`JWT_SECRET` — это защита от случайного запуска с сгенерированным секретом,
который потерялся бы при перезапуске и разлогинил всех.

```
JWT_SECRET=<длинная случайная строка>
```

Сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

В разработке переменная не нужна — секрет создаётся сам и лежит в
`server/data/.jwt-secret`.

## 3. client_max_body_size в nginx

Nginx по умолчанию режет тело запроса на 1 МБ, а API принимает файлы до 25 МБ.
Без этой строки загрузка PDF будет падать с невнятной ошибкой 413:

```
client_max_body_size 25m;
```

## 4. Что отдавать напрямую, а что проксировать

```
/api/      -> Node (порт 3000)
/uploads/  -> server/uploads/ напрямую с диска, минуя Node
всё остальное -> dist/, с фолбэком на index.html
```

Фолбэк на `index.html` обязателен: маршруты вида `/products/series-x` и
`/admin/...` существуют только в браузере. Без него любое обновление страницы
даст 404.

Express умеет отдавать и статику, и `/uploads` сам (так работает локально),
так что при желании можно проксировать в него вообще всё — просто медленнее.

## 5. Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `JWT_SECRET` | Подпись сессий, **обязательна в production** | — |
| `PORT` | Порт Node | `3000` |
| `NODE_ENV` | `production` включает secure-куки | — |
| `KAE_DB_PATH` | Файл БД | `server/data/kae.db` |
| `KAE_UPLOAD_DIR` | Папка загрузок | `server/uploads` |

Куки помечаются `secure` только при `NODE_ENV=production` — то есть сайт должен
работать по HTTPS, иначе браузер не сохранит сессию и вход в админку не сработает.

## 6. Данные лежат вне репозитория

В git не попадают (и правильно): `server/data/` — база, `server/uploads/` —
загруженные файлы, `dist/` — сборка, `_source-photos/` — исходные снимки и сканы.

Бэкап — это копия двух каталогов:

```
server/data/      база (файл kae.db + wal)
server/uploads/   все изображения и PDF
```

Копировать базу лучше средствами SQLite, чтобы не поймать её в момент записи:

```
sqlite3 server/data/kae.db ".backup '/куда/kae-$(date +%F).db'"
```

## 7. Первый запуск

```
npm ci
npm run build          # собирает dist/
npm run db:seed        # создаёт схему и администратора, печатает пароль
npm run server
```

`db:seed` печатает сгенерированный пароль **один раз** — дальше он только в виде
bcrypt-хеша. Можно задать свой заранее:

```
ADMIN_EMAIL=you@example.kz ADMIN_PASSWORD=... npm run db:seed
```

Повторный запуск `db:seed` безопасен: существующие записи не трогаются.

## 8. Обновление кода

```
git pull && npm ci && npm run build && systemctl restart <сервис>
```

Схема БД применяется сама при старте, отдельных миграций гонять не нужно.

## 9. Перенос фото продукции

Снимки уже импортированы в медиатеку. Если понадобится повторить на сервере —
положите папки в `_source-photos/` и выполните:

```
node server/db/import-photos.js
```

Скрипт идемпотентен: файлы сверяются по содержимому, товары — по адресу.
